# ASSIGN-023 — Lives tracking, death detection, respawn (GameStateMachine)

Implemented in `src/engine/state/GameStateMachine.ts`:
- `GameStateMachine` class: starts each game with `DEFAULT_GAME_CONFIG.startingLives` (3),
  tracks `screen`/`level`/`lives`, exposes `startGame`, `beginPlaying`, `handleGhostCollision`,
  `getLives`, `getScreen`, `getLevel`, `getSnapshot`, `subscribe`.
- `handleGhostCollision(ghostMode)`: fatal only for `chase`/`scatter` ghost modes (scared/eaten
  are safe), decrements lives, transitions to `countdown` (respawn) if lives remain, or
  `gameOver` if lives reach 0.
- `respawnEntities(layout)`: pure function that returns fresh copies of Pac-Man/ghost positions
  for a respawn. Takes no dot/pellet/maze state as input and returns none, so maze-clearing
  progress (owned by the Maze module) is structurally guaranteed to survive every respawn.

Tests in `src/engine/state/GameStateMachine.test.ts` cover all 4 acceptance criteria of US-016
with tags `[US-016#1]`..`[US-016#4]`, including a dedicated test proving dot state is untouched
across a death -> respawn cycle.

No other modules were modified; GameLoop wiring (TASK-049/050 consumption) is out of scope for
this assignment per the repo contract (MOD-GAMELOOP is a separate declared module).
